
## 2. API Endpoints Reference

All endpoints are versioned under `/api/v1/`:

| Method | Endpoint | Description | Response Status |
|---|---|---|---|
| `GET` | `/api/v1/health` | Service health, API/app version, and frozen subsystem states | 200 OK |
| `POST` | `/api/v1/jobs` | Initialize and execute a pipeline job (`DEMO_FUSION`, `ARTIFACT_FUSION`, `PHYSICAL`) | 201 Created / 400 Bad Request / 422 Unprocessable Entity |
| `GET` | `/api/v1/jobs` | List recently executed jobs with limit parameter | 200 OK |
| `GET` | `/api/v1/jobs/{job_id}` | Retrieve complete current manifest and state of a job | 200 OK / 404 Not Found |
| `GET` | `/api/v1/jobs/{job_id}/artifacts` | Discover all machine-readable artifacts generated by a job | 200 OK / 404 Not Found |
| `GET` | `/api/v1/jobs/{job_id}/result` | Retrieve normalized Evidence Fusion result (evidence graph, hypotheses, ledger) | 200 OK / 403 Forbidden / 404 Not Found / 500 Error |

## 3. Canonical Job & Stage Lifecycle

### Job Status Vocabulary
- `CREATED`: Job initialized in workspace.
- `VALIDATING`: Validating input parameters, artifact paths, and security constraints.
- `RUNNING`: Executing pipeline stages.
- `SUCCEEDED`: Finished successfully; normalized result and artifacts populated.
- `FAILED`: Execution terminated with structured error descriptor.
- `BLOCKED_PROVENANCE`: Physical execution blocked due to unaccredited or missing operational feeds.
- `INVALID_INPUT`: Malformed payload, path traversal attempt, or negative tolerances.

### Pipeline Stage Vocabulary
1. `VALIDATE`: Validates mode, pipeline type, tolerances (> 0), path traversal (`..` rejection), and operational feed accreditation.
2. `INGEST`: Loads multi-source evidence (synthetic demo fixture or repository GeoJSON/JSON artifacts).
3. `FUSION`: Executes Multi-Source Evidence Fusion V1, resolves independent source clusters, and evaluates candidate origin/vessel hypotheses.
4. `EXPORT`: Serializes `evidence_graph.json`, `evidence_summary.json`, and `evidence.geojson` to the job workspace, registers artifacts, and compiles final result.

## 5. DEMO vs. PHYSICAL Provenance Behavior

- **`DEMO` Mode**:
  - Validated for local development, algorithm inspection, and integration testing.
  - Combines deterministic synthetic evidence fixtures (`generate_deterministic_demo_fusion_fixture`) or repository historical GeoJSON artifacts.
  - Generates full evidence graphs, candidate vessel hypotheses, and limitations notices.
- **`PHYSICAL` Mode**:
  - **Strictly Fails Closed**: Operational external satellite downlinks and live commercial AIS feeds are unaccredited in this milestone (`BLOCKED — AWAITING_OPERATIONAL_SOURCE`).
  - The API and Orchestrator **never** substitute DEMO data into PHYSICAL requests.
  - The API and Orchestrator **never** relabel DEMO data as PHYSICAL.
  - Invocations with `mode: "PHYSICAL"` produce `status: "BLOCKED_PROVENANCE"`, stage `VALIDATE` as `BLOCKED`, error code `PROVENANCE_REJECTION`, and `GET /jobs/{id}/result` returns HTTP 403 Forbidden.
